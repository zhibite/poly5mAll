回测里的“观察价止盈”到底是什么
回测的循环逻辑其实很简单：


target = entry_price * (1 + tp)      # 例如 0.25 × 1.10 = 0.275

for t in prices[60s : 240s]:         # 每秒（或每5秒）一个样本
    if t.price >= target:
        exit_price = t.price         # ← 关键：按“看到 target 的那一秒的价格”成交
        break
else:
    exit_price = price_at_240s       # 没触发就 240s 平仓
注意 exit_price = t.price 这一行：它不是 target，而是触发时那一秒/那 5 秒的实际观察价。如果价格从 0.27 直接跳到 0.42，回测就按 0.42 卖出，而不是按 0.275 卖出。这就是“观察价止盈”，也是 +6,627U 的来源。

实盘程序怎么做
策略状态机本身很简单：

市场开始后 0–60s，监听 UP/DOWN 价格；
任一边价格 ≤ entry_thresh，买入 10U；
记录成交价，算出 target = fill_price × (1 + tp)；
60–240s 监控价格；
到 target 就卖，没到就在 240s 卖。
难的不是逻辑，是“卖”的那一下。 实盘有三种做法：

做法	成交价	能吃到越价吗	可控性
A. target 挂限价卖单	基本等于 target	❌ 吃不到	高，成交确定
B. 价格触发后发市价/追价单	当时最优买价，未知	✅ 可能吃到	低，受延迟/滑点影响
C. target 触发后启动 trailing stop	回撤一定比例后成交	部分	中等，参数敏感
回测的“观察价止盈”最接近 B，但假设了零延迟、无限流动性、能按那一秒的价格成交。实盘做不到这么理想。

好不好控制？
策略逻辑好控制，盈利性不好控制。

几个关键问题：

你看到的是 last price，不是可成交价
回测用的是价格序列；实盘买入要付 ask，卖出要拿 bid。5m 市场点差可能不小。

点差就能吃掉全部 edge
按 entry≈0.27、10U 仓位 ≈ 37 份计算：

1 美分往返点差 ≈ 0.37U/笔；
而 0.25/10% 的均盈只有 +0.234U/笔。 也就是说，1 美分点差就足以把策略打成负期望，还没算滑点和手续费。
越价不是免费午餐
回测里“跳到 0.42 就卖 0.42”，实盘需要你在那一瞬间有可成交的买盘。如果你挂 target 限价，只能拿 0.275；如果你追市价，可能成交在 0.38，也可能成交在 0.30，取决于延迟和盘口深度。

240s 平仓同样不可控
回测按 240s 的 last price 平仓；实盘如果是市价单，尾部那 25%–30% 的亏损可能比 −9.3U 更深。

数据频率不够
当前回测的入场窗口用的是 5s 的 lead 数据，止盈用 1s/5s K 线。实盘需要更细的盘口/逐笔数据才能校准。
